# 全渠道模型准入检查与修复（2026-09-22）

## 范围

移除代码内置的模型名称白名单/前缀准入限制，尊重管理员配置的模型和映射。
扫描范围包含 relay/channel（聊天、图片、任务）、relaykit、controller、
relay/helper、middleware 及后台渠道配置界面。
ModelList 等目录仅推荐展示。管理员新增名称仍需配置渠道模型、分组权限和价格；
本次不取消令牌模型权限、后台路由或管理员自行设置的模型规则。

## 已处理

| 渠道 | 修改 |
| --- | --- |
| manying | 移除名称准入及依赖固定型号的二次价格准入；支持JSON和multipart新名称 |
| shafu | 移除内置目录校验，避免manying继承路径再次拦截 |
| AutoDL H3 | 任意配置workflow ID用于请求路径；按显式素材/模式选择已有请求结构，保留seed及素材 |
| longxia6 | 删除型号能力表，时长/提示词/素材数量/画幅/组合交上游校验 |
| sd0717 | 使用管理员映射的上游名称；只保留未映射的sd0717渠道标签旧默认值 |
| Vidu | 参考生成不再把viduq2-pro/turbo或新名称强制改为viduq2 |
| Gemini、Vertex | Imagen兼容图片协议按请求端点选择，不再以imagen前缀作为准入；路径和响应解析一起调整 |

满聚、naonao 的模型名称白名单此前已移除；其余检查到的ModelList用途为目录展示，
不是请求拒绝条件。已知模型的协议转换分支（如百度历史路径、聊天/embedding协议）
不等于准入白名单，保留正常路由行为。

## 保留的边界

- 模型非空、JSON结构、字段冲突、鉴权、资源大小、URL安全和计费溢出保护。
- 适配器尚不能表达的协议输入仍会明确拒绝，不通过删除检查来静默丢素材。
- 协议放开不意味着上游支持所有模型或接口；不支持时由上游返回错误。
- Gemini/Vertex图片端点仍使用Imagen predict协议，原生Gemini generateContent路径保持独立。
- manying启用分辨率计价时：已知型号保留原定价档位；新名称需要显式resolution或像素size。
  缺档位返回价格错误，不能猜测清晰度或按零额度提交。该字段用于价格档位选择，
  不声称修改上游模型固定的输出清晰度。
- 本次不迁移历史收费规则，包括longxia6的-PerSecond识别和各渠道既有倍率。
  “按次/按秒完全由后台显式配置”的迁移仍需单独核对线上价格。

## 回归

新名称/重命名、JSON和multipart继承链、协议请求与响应一致性、
管理员模型不被改写、素材与seed保留、已知模型正常请求、
基础价格和分辨率计价非零、缺少价格档位明确失败。
