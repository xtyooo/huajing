## 1. 来源边界与日期约定

本窗口跨度较长，早期上下文已压缩：可见用户请求保留了主要顺序，但不能保证早期助手的每一条回复或每一次命令均可恢复。本次结合当前可见对话、同一线程恢复出的 19 条早期助手最终回复、Git 提交、Trellis 任务归档、现有代码和测试整理。

本文区分四类证据：

- **代码/记录核实**：2026-10-12 文档整理时读取的提交、现有代码、测试及归档结果。
- **历史助手报告**：当时最终回复称已执行的部署、诊断或恢复；没有重新连接生产，不等于今天再次核实。
- **用户报告**：原始问题、截图或请求明确，但缺少完整调查记录；只记录现象，不补造根因。
- **风险/待办**：防复发规则或未完成工作，不能写成已经发生或已经解决的事故。

有提交日期的事件使用 Git 日期；用户可见时间使用 `Asia/Shanghai`。没有可靠日期的早期事件按对话顺序归组，不把压缩上下文推断成精确时间。私钥、API Key、COS 凭据、数据库连接串和临时签名 URL 参数均不保留。

## 2. 一直不变的目标与后来确立的工作方式

最初目标是：保持画境二开功能不变，按官方源码升级。随后窗口内大量工作转向视频渠道、标准协议兼容、缓存、收费和安全部署。用户多次要求“先排查”“深度检查”“不用非要本地启动”，因此只需诊断时不能擅自上线；请求修复/部署时才执行对应变更。

最终已确立的长期约定：

1. 用户侧继续使用画境标准视频协议，适配器负责上游差异；后台配置 API Key、地址、公开模型、映射、分组及售价。
2. 推荐模型目录不是白名单。管理员配置新增或改名模型不能被内置名字挡住；上游负责型号能力校验。
3. 不根据模型名称、前后缀或文档库存快照猜测能力与计费；保留结构、鉴权、归属、SSRF、资源及收费溢出保护。
4. 上游生成完成不等于画境任务完成。需要缓存的渠道必须缓存成功、有稳定 URL 后才对外成功/100%；缓存期间进行中/99%。`kuai` 是明确约定的免缓存例外。
5. 用户侧价格与上游成本独立。按秒/按次由后台公开模型设置，模型映射不得改变售价；不能静默零收费、重复乘秒数或自动迁移线上账单。
6. 当前永久开发/发布分支是 `dev`，规范工作区是 `.worktrees/dev`。历史的 `upgrade/*`、`integrate/*`、`feat/*` 决策仅代表当时，不作为今天常规开发模板。
7. 双实例代码发布使用 COS 构建一次、上传一次、小太阳先行、画境随后；备份、校验、日志、品牌及数据库隔离是交付内容，不是可省的附带步骤。

完整规则见 [AGENTS.md](../AGENTS.md) 和 [渠道长期约定](./channel-integration-policy.md)。

## 3. 2026 年 7 月：升级、缓存和最初部署

### 3.1 官方升级与本地验证障碍

用户提供《New-API二开升级指导》，要求现有功能保持不变并更新官方代码。早期报告中前端依赖安装受到本机 `CERT_HAS_EXPIRED` 阻拦，类型检查和构建尚未完成，`go vet` 存在官方原有问题；用户要求排查，并明确不必强行本地启动、重点检查问题。

这些是**报告过的验证障碍**。当前可恢复资料不足以复述证书根因、每个 vet 问题或早期修复细节，不应将它们写成已确认的某种代理/证书故障。后续提交和发布有新的完整测试证据，但不能用后来的通过倒填早期检查结果。

### 3.2 缓存设置不保存、下载慢和返回 JSON

用户报告后台缓存相关数值“保存后刷新恢复原值”，要求检查对应缓存脚本；又报告千兆网络下视频缓存长期不完成。随后举例任务生成成功，媒体地址却为 `.json` 而不是 MP4，并提供相关 Sora 接入文档，询问现有 Sora 渠道协议是否匹配。

这些问题推动排查配置保存链路、上游结果包与实际媒体下载链路。早期完整修复记录不足，本文不声称当时某字段或数据库写入已被定位；可以确定的是，后续工作不能只依据网速、地址后缀或上游 `SUCCESS` 断言媒体可用。

### 3.3 上线、页面紧急故障与 403

用户要求梳理改动、部署升级、注意备份和日志，先提供旧服务器，后采用手动上传。上线后列出 profile、invitation-records、channels、models/metadata、users、dashboard/models 六个页面，报告紧急故障；又询问从 `2026-07-14 23:56:10` 起出现 `download failed with status 403 Forbidden`。

可恢复对话确认这些事件发生过，但不足以对六页面事故或早期 403 给出可靠根因及逐项闭环。不能笼统称“前端缓存”“上游封禁”或“已全部修复”。这类事件须按 [踩坑指南的故障证据门槛](./development-pitfalls.md#诊断与验收停止条件)重新查具体任务/HTTP目标/日志。

### 3.4 下载占槽与并发

用户报告许多任务卡在下载中，阻挡后续任务进入下载，要求排查并修复，随后明确要求同时下载数提高到 `100`。这是历史并发需求，不是今天生产并发已经核实为 100 的证据。提高并发也不能替代超时、取消、槽位释放、重试和排队可观测性。

这是**助手没有接通后台已有计费模式**导致的真实功能缺口，不能只称用户配置不当。避免零收费的 guard 有作用，但不能把它当最终功能交付；正确方案是支持后台按秒售价，不是删除guard后零收费、改名字或要求用户放弃按秒模式。

`81580dd69` 实现公开模型分辨率价格、明确时长/档位、绝对额度、一次时长乘法、分组倍率、已有预扣/结算/退款/审计。固定价格保持原行为；无价格、缺时长、自动 `-1`、透传冲突等在按秒模式明确失败。独立审查还发现初版“收费档位正确但像素 size 被错误提升成 resolution”的 wire 问题，修复后才冻结发布。

本地隔离钱包与 HTTP mock 验证720p/10秒/组倍率1，预扣、结算、消费日志均 `$2.80`；截图三档10秒为 `$2.30/$2.80/$3.30`。该钱包 fixture 是 playground，不覆盖 token 实扣；token/退款依赖既有 service 回归，不可夸大为这条 fixture 已直接验证全部钱包类型。
