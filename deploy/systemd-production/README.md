# New API systemd 生产发布

这套脚本用于当前服务器的 systemd 部署，应用仍会使用原来的 `.env`、媒体目录和日志位置，新程序放到 `/apps/releases/<发布编号>`，切换时不会覆盖旧二进制。

`deploy.sh` 会先检查程序校验值和内外网状态，再停止应用，备份数据库、配置、旧程序、媒体硬链接快照和关键日志，完成后用 systemd 覆盖文件切换新目录；新版本在 60 秒内无法通过内网检查，脚本会自动恢复原来的服务配置。

媒体文件按硬链接保存到 `/apps/backups/<发布编号>/files/media`，不会再复制一份 11 GB 数据，删除原媒体后仍可以从备份恢复；媒体文件应保持只读使用，不能直接修改文件内容。MySQL 会导出为 `mysql.sql.zst`，密码只在备份进程的环境变量中使用，不会写入命令参数和运行日志。

执行发布：

```bash
chmod 700 deploy.sh rollback.sh
./deploy.sh <发布编号> <Linux 程序 SHA256>
```

只回退程序，不恢复数据库：

```bash
CONFIRM_ROLLBACK=<发布编号> /apps/releases/<发布编号>/rollback.sh <发布编号>
```

数据库恢复会覆盖上线后的新数据，这套脚本不会自动执行数据库恢复，需要停止业务写入并人工确认备份内容后再操作。
